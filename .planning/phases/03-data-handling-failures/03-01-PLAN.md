## BUG-04: Duration Calculation Failures

### Problem Summary
Duration calculation fails silently in multiple places, returning 0 without error indication. Users have no way to know if duration is genuinely 0 or if an error occurred.

### Locations to Fix

#### 1. `services/assembly_service.py` (Lines 813-816)
**Current behavior:**
```python
try:
    info = mediainfo(source_path)
    audio_duration_ms = int(float(info.get('duration', 0)) * 1000)
except:
    audio_duration_ms = 0
```
**Problem:** Bare `except:` catches all exceptions, returns 0 silently.

**Fix:**
- Use specific exception type (`Exception`)
- Log error with file path and exception details
- Return `None` to indicate failure (distinguish from actual 0ms)

#### 2. `controllers/video_player_controller.py` (Lines 102-104)
**Current behavior:**
```python
self.fps = self.video_capture.get(cv2.CAP_PROP_FPS)
self.total_frames = int(self.video_capture.get(cv2.CAP_PROP_FRAME_COUNT))
self.duration_ms = int((self.total_frames / self.fps) * 1000)
```
**Problem:** No validation of fps > 0, could cause divide-by-zero or garbage values.

**Fix:**
- Validate fps > 0 before division
- Show error dialog if video metadata is invalid
- Log warning with details

#### 3. `controllers/file_handler.py` (Lines 46-50)
**Current behavior:**
```python
duration_ms = data.get("duration_ms", 0)
if duration_ms < 0:
    data["duration_ms"] = 0  # Silent correction
```
**Problem:** Silently corrects invalid data without user notification.

**Fix:**
- Show warning dialog for invalid duration
- Log the correction with file path
- Let user decide whether to proceed

### Implementation

**Change 1: Create duration validation utility**

**File:** `core/validation.py` (new file)

```python
def validate_duration_ms(duration_ms: int, source: str) -> int:
    """
    Validate duration value, raise ValueError if invalid.

    Args:
        duration_ms: Duration to validate
        source: Description of source for error messages

    Returns:
        Validated duration (unchanged if valid)

    Raises:
        ValueError: If duration is negative
    """
    if duration_ms < 0:
        raise ValueError(f"Invalid duration {duration_ms}ms from {source}")
    return duration_ms
```

## BUG-05: Marker Dict/Object Type Confusion

### Problem Summary
Markers are sometimes dicts, sometimes Marker objects. Code uses scattered `isinstance(marker, dict)` checks, creating duplication and potential bugs when checks are missed.

### Root Cause
The codebase has both legacy dict markers and newer Marker objects. Different services handle them inconsistently.

### Solution Strategy
**Normalize at boundaries**: Convert all markers to dicts at the entry points of services. This is simpler than converting everything to Marker objects because:
1. JSON import/export uses dicts naturally
2. Most code already handles dicts
3. Marker objects are only used in some places

### Locations to Fix

| File | Lines | Issue |
|------|-------|-------|
| assembly_service.py | 61-66, 84-114, 148-168 | Duplicate isinstance checks |
| assembly_playback_service.py | 202-205, 262, 287-288 | Scattered isinstance checks |
| audio_service.py | 881-884 | Assumes dict without check |
| marker_repository.py | 78 | Type hint mismatch |

### Implementation

**Change 1: Create marker normalization utility**

**File:** `core/marker_utils.py` (new file)

```python
"""Utilities for consistent marker handling"""

from typing import Union, Dict, Any, List

def normalize_marker(marker: Union[dict, Any]) -> dict:
    """
    Convert marker to dict format for consistent handling.

    Args:
        marker: Either a dict or Marker object

    Returns:
        Dict representation of marker
    """
    if isinstance(marker, dict):
        return marker

    # Convert Marker object to dict
    return {
        'name': getattr(marker, 'name', ''),
        'type': getattr(marker, 'type', 'sfx'),
        'time_ms': getattr(marker, 'time_ms', 0),
        'duration_ms': getattr(marker, 'duration_ms', 0),
        'versions': getattr(marker, 'versions', []),
        'current_version': getattr(marker, 'current_version', 0),
        'asset_file': getattr(marker, 'asset_file', ''),
        'prompt_data': getattr(marker, 'prompt_data', {}),
        'assigned_track': getattr(marker, 'assigned_track', None),
        'assigned_channels': getattr(marker, 'assigned_channels', []),
    }

def normalize_markers(markers: List[Union[dict, Any]]) -> List[dict]:
    """Normalize a list of markers to dicts"""
    return [normalize_marker(m) for m in markers]

def get_marker_attr(marker: Union[dict, Any], key: str, default=None):
    """
    Get attribute from marker regardless of type.

    Args:
        marker: Dict or Marker object
        key: Attribute name
        default: Default value if not found
    """
    if isinstance(marker, dict):
        return marker.get(key, default)
    return getattr(marker, key, default)
```

from core.marker_utils import normalize_marker

def add_marker(self, marker: Union[dict, object]) -> None:
    """Add a new marker and maintain time-based sorting."""
    # Normalize to dict for consistent storage
    marker_dict = normalize_marker(marker)
    self._markers.append(copy.deepcopy(marker_dict))
    self._markers.sort(key=lambda m: m["time_ms"])
    self._notify_change()

## Edge Cases

- Video with 0 frames but valid fps → duration = 0 (valid, not error)
- Audio file with no duration metadata → log warning, duration = None
- Marker object with missing attributes → use defaults from normalize_marker
- Empty markers list → skip processing, no errors
